# Правила работы с OpenCode

Как агент OpenCode (AI-агент в терминале) работает с проектом *The Drowned Lands*: зона ответственности, команды верификации, MCP-рабочий процесс и ограничения.

## Роль OpenCode

OpenCode работает со всем проектом: код, сцены, скрипты, конфиги — через терминал. Он использует плагин `addons/godot_mcp` для управления редактором Godot.

## Godot не в PATH

Бинарь Godot не находится в `PATH`. Рекомендуется задать переменную окружения в `~/.bashrc`:

```bash
export GODOT="$HOME/.local/bin/godot"
```

> Предпочтительно — `$HOME/.local/bin/godot` или проект-локальный Godot_v4.7.2 (`$HOME/.local/godot.app/bin/godot`) при наличии: если пути `godot.app` нет, используй `$HOME/.local/bin/godot`. Значение `GODOT_MCP_GODOT_BIN` указывает на фактический бинарь MCP.

Во всех командах верификации ниже используется `$GODOT`.

## Команды верификации

- **Парс-проверка одного скрипта** (`--check-only --script res://path/to/script.gd`) — ловит `SCRIPT ERROR`, exit 1 при ошибке. Использовать как основную синтаксическую проверку.
- **Сканирование проекта** (`--import`) — импорт/сканирует весь проект, exit 0 при успехе. **Не ловит** GDScript parse errors — не использовать как синтаксическую проверку.
- **Smoke-тест** (`--quit`) — быстрый прогон только при установленной главной сцене (`application/run/main_scene` = `res://main.tscn`). Выходит сразу после запуска.

Порядок после изменений: `--check-only` по каждому изменённому скрипту → `--import` по всему проекту.

## MCP-рабочий процесс

1. `opencode.json` определяет секцию `godot-mcp`, которая запускает `godot-editor-mcp` (stdio, локально).
2. MCP-сервер управляет **живым редактором Godot** через `ws://127.0.0.1:9080` — плагин `addons/godot_mcp` должен быть включён в редакторе, иначе сцены, скрипты и рантайм недоступны.
3. По умолчанию доступны только тулсеты `core` + `inspection`. Остальные (например `scene_edit`, `scripts`, `runtime`) включаются через `godot_enable_toolset`.
4. Мутирующие инструменты используют `dry_run=True`; деструктивные требуют `confirm=True`.
5. Если Godot не в `PATH`, headless-вызовы MCP падут с «no Godot available» — установить `GODOT_MCP_GODOT_BIN` в окружении MCP.

## Границы

- `docs/` — зона Cline/OpenKnowledge: редактируется вручную через OK MCP, **не через shell**.
- Всё остальное (код, сцены, `project.godot`, конфиги) — через OpenCode и godot-mcp.
- При попытке выйти за границы Cline обязан остановиться и запросить разрешение.

## Готчи

- Аддон `godot-ai-autonomous-agent` указан в `project.godot` как включённый, но **не существует**. При старте редактор выводит предупреждение и удаляет его из списка — это не баг, игнорировать.
- `project.godot` перезаписывается редактором при сохранении — править его через editor/MCP, а не на диске, пока редактор открыт.
- Editor UI имеет русский локализационный набор: прогресс и ошибки Godot могут быть не на английском — ориентироваться на метки `ERROR`, `SCRIPT ERROR`, `WARNING` и коды выхода.

## Правила агента

- Одна задача — один запрос.
- Ссылаться на источник: `Read docs/...` (для Cline) или на соответствующий скрипт/сцену (для OpenCode).
- Требовать верификацию: `--check-only`, `--import`, дифф.
- После изменений структуры проекта (новые/удалённые файлы в `scripts/`, `assets/`, `docs/` корневого уровня) — обновлять `docs/tree.md` командой `tree` (или аналогом) и коммитить дерево вместе с остальными изменениями, если коммит запрошен.

## Версионирование и push

- **Push только после явного «пуш» от пользователя.** Не делать авто-push.
- **Перед push:** закоммитить все значимые изменения; обновить `docs/tree.md`, если изменилась структура дерева.
- **Bump в `scripts/main.gd` + `docs/build-status.md`: MINOR** — при добавлении механик/экранов или изменении session API; **MAJOR** — при ломающих изменениях мира и сессии.
- **PATCH** — для UI/баланса/текстов без изменения session API.
- **Не коммитить** `.godot/`, логи, `session-*.md` и сырые тяжёлые бинарники из `drafts/` без необходимости.

## UI и ассеты

- Шрифты лежат в `assets/fonts/`. Сейчас в проекте **Forum-Regular.ttf** (заголовки, OFL) и **Inter** (UI/body, OFL, переменная). **Cinzel-Variable.ttf** present but not loaded. **SourceSans3-* и TwemojiMozilla удалены.**
- Иконки HUD — не эмодзи, а процедурные глифы в `scripts/icon_glyph.gd` (класс `IconGlyph`). При добавлении новой иконки — новый `Kind` в `enum Kind` + отрисовка в `_draw()`.
- Промпт на визуал (`main.gd` / `board.gd`) не меняет геймлогику (`Actions`, `Turn`, `Reachability`), если это не оговорено явно.
- После UI-правок: `$GODOT --headless --path . --import` и `--check-only` по проекту. Учти, что `main.gd` в режиме `--check-only` падает с `Identifier not found: GameState` — это ограничение single-script-режима (autoload не регистрируется); ориентируйся на `--import` и на `--quit`.
