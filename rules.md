# Правила вики

Эта страница задаёт конвенции оформления для всех редакторов — людей и ИИ-агентов. Перед изменением вики прочитайте её и [главную страницу](./index.md).

## 1. Структура и порядок разделов

Вики описывает концепт игры *The Drowned Lands*. Разделы вики должны быть расположены в строгом логическом порядке (от общего к частному). Новая механика вставляется в этот порядок по смыслу, а не в конец.

## 2. Порядок списков

- **Сборочные списки** (жанры, референсы, похожие игры, народы, монстры, локации, постройки, характеристики, соратники и т.п.) — в алфавитном порядке.
- **Таблицы** сортируются по значению, если это логика таблицы (пример: [Высота объектов](./flood.md#высота-объектов) — по убыванию диапазона). Порядок закрепляется в таблице и не меняется без причины.
- **Исключения, где сохраняется логический/хронологический порядок:** цикл сезонов (Ахет → Перет → Шему → эпагоменалы), числовые последовательности по годам, оглавления (список разделов, список подстраниц)

## 3. Метка TBD

Недописанный блок завершается строкой:

```text
**TBD:** что именно осталось описать.
```

и страница получает тег `tbd`. Метку удаляют только после заполнения блока.

## 4. Орфография и пунктуация

- Язык — русский; все внутриигровые термины, сезоны, названия механик и предметы пишутся на кириллице: **Ахет, Перет, Шему, Эпагомены**, «народ» (не «нация»), «моряки» (не «мореходы»), «отряды» (не «юниты»), «шекели» (не «деньги»), «талант» (не «килограммы»).
- Пункты перечней и абзацы заканчиваются точкой; ячейки таблиц пишутся без завершающей точки.

## 5. Ссылки

- Термин, у которого есть страница, связывается ссылкой при первом упоминании на странице.
- Используй **относительные пути** (`[text](./sibling.md)`) — рекомендуемый дефолт; допустимы **корневые пути** с ведущим слэшем (`[text](/rules.md)`).
- Все страницы вики лежат в одной папке `docs/`. Вложенных папок нет — только технические (`node_modules/`).
- **Не склеивай** `./` с корневым путём — `./folder/doc` из документа внутри `folder/` даёт «умноженный» невалидный путь.
- **Внешние веб-URL не пишут в тело.** Источник помещают в `sources:` фронтматта, а в теле цитируют локальный документ: `[название источника](./external-sources/source-slug.md)`.
- Перед каждым `write`/`edit` проверять разрешаемость всех ссылок (`brokenLinks` / `audit`).

## 6. OKF-фронтматтер (Open Knowledge Format v0.2)

Каждый `.md`-документ (кроме `index.md` и `log.md`) должен начинаться с валидного YAML-блока фронтматтера между строками `---`.

### 6.1. Минимум (конформантный пол)

- **`type` — единственное всегда-обязательное поле.** Короткая самодостаточная строка, описывающая концепт (`Mechanic`, `Setting`, `Document`, `Reference`, `Playbook`, `API Endpoint`). Значения не регистрируются централизованно — выбирайте понятные описательные названия.
- Отсутствие `type` или `type: ""` / `type: "   "` (только пробелы) — **нарушение**.

### 6.2. Рекомендуемый фронтматтер

```yaml
---
type: Mechanic
description: "Краткое описание концепта в одном предложении."
tags:
  - тег1
  - тег2
sources:
  - resource: "./external-sources/source-slug.md"
    title: "Название источника"
generated:
  at: "2026-10-07T12:00:00Z"
status: draft
stale_after: "2026-12-31T00:00:00Z"
verified:
  - by: human:<id>
    at: "2026-10-07T12:00:00Z"
---
```

| Поле | Обязательность | Примечание |
| --- | --- | --- |
| `type` | **Да** | Конвейер/фильтрация по типам |
| `description` | Нет | Краткое резюме; полезно для навигации |
| `tags` | Нет | Массив строк, в т.ч. `tbd` для недописанных блоков |
| `sources[].resource` | **Да, при наличии `sources`** | Внешний/внутренний ресурс: абсолютный URL, относительный путь или `references/…` |
| `generated.at` | Нет | ISO 8601 c UTC-сдвигом — момент генерации/последнего осмысленного изменения |
| `status` | Нет (по умолчанию `stable`) | `draft` — не проверено/неполно; `stable` — готово к потреблению; `deprecated` — устарело, сохранено для ссылок |
| `stale_after` | Нет | Абсолютный момент, после которого контент считается устаревшим |
| `verified[]` | Нет | Кто/что подтвердило факт против источника; отсутствие = «не проверено» (допустимое состояние) |

### 6.3. Зарезервированные имена

- **`index.md`** — зарезервированное имя на любом уровне иерархии. Не должно иметь фронтматтера (кроме корневой `index.md`, где допускается ключ `okf_version`).
- **`log.md`** — не подчиняется ограничениям OKF §9 (даты-заголовки, порядок, проза), фронтматтер не ограничивается.

### 6.4. Запрещено

- Писать сырые `https://…`-ссылки в тело документа — это **TODO**, а не цитата. Внешний источник должен быть сохранён через `ingest` в `external-sources/` и цитироваться локально.
- Редактировать `.md`-файлы через `rm`/`sed`/`Bash` — только через OK MCP (`write`, `edit`, `delete`, `move`), иначе теряется CRDT-атрибуция.
- Фронтматтер из **папки не наследуется** в документы: значения задаются в каждом документе либо через шаблоны (`write({ template })`).

## 7. Изображения и медиа

- **Только markdown-синтаксис:** `![осмысленный альт-текст](./путь/к/картинке.png)`. Не использовать HTML `<img>` — такие вставки не участвуют в контентном графе OpenKnowledge и могут не рендериться согласованно на published-поверхностях (GitHub Pages / Fumadocs).
- **Путь должен быть относительным к документу** — `./image.png`, `../assets/foo.png` или корневой `/assets/foo.png`. Не писать серверные/сетевые URL (`http://…`, `127.0.0.1`, `preview_url`).
- **Сохранять файлы локально, не hot-linkить.** Картинку из интернета сначала нужно сохранить в дерево (через `ingest` в `external-sources/`), а потом ссылаться на локальный файл.
- **Альт-текст обязателен** и должен описывать, *что именно* изображено, а не просто называть файл. Пустой `![]()`, `![image]()`, `![filename.png]()` считаются нарушением — альт-текст индексируется и влияет на поиск.
- **Сетевые изображения подписывать** источником под картинкой:

```markdown
  ![Анг прибегает к силе Аватара](./external-sources/avatar-wiki-aang.png)
  *Источник: [Avatar Wiki — Анг](./external-sources/avatar-wiki-aang.md)*
  ```

## 8. Визуальные компоненты (markdown-native)

OpenKnowledge автоматически превращает markdown-native синтаксис в стилизованные компоненты. **Использовать markdown-native форму — а не JSX.** Продвинутый компонент стилизуется, доступен и участвует в контентном графе; ручной JSX — ни того, ни другого.

| Нужно | Писать (markdown-native) | Превращается в |
| --- | --- | --- |
| Выноски / замечания | `> [!NOTE]` + тело; доступны типы NOTE, TIP, IMPORTANT, WARNING, CAUTION; `+` делает collapsible | стилизованная Callout |
| Свёртываемая секция | `<details><summary>Заголовок</summary>` … `</details>` | стилизованный Accordion |
| Диаграмма | ```mermaid (flowchart, sequence, class, state, ER, gantt, pie) | Mermaid-диаграмма |
| Подсветка | `==текст==` | mark-выделение |
| Встроенный документ или ассет | `![[file]]` | wiki-вставка |

- **Эти разделители — живые и работают прямо в прозе.** `==`, `$`, `$$`, `%%`, `<!--` … `-->` и `~~` форматтируют или скрывают текст, где бы они ни стояли. Чтобы показать их буквально, обернуть в inline-code (`` `==x==` ``) или экранировать (`\==x\==`, `\$5`, `\%\%note\%\%`, `\<!-- note -->`). Особое внимание на `%%` и `<!-- -->`: случайная пара не перекрашивает текст, а скрывает его.
- `html preview` — это отдельный механизм: `` ```html preview ``` `` даёт песочницу с iframe для графиков и кастомных элементов; в нём **нельзя хардкодить цвета** (`#fff`, `rgb()`), нужно использовать токены темы: `var(--foreground)`, `var(--chart-1..5)`, `var(--card)`, `var(--background)`, `var(--border)`, `var(--primary)`, `var(--radius)`.

## Границы для AI-агентов

Этот раздел вики редактируется агентом Cline через OpenKnowledge. Агент ограничен папкой `docs/` и не имеет права изменять:

- файлы игрового проекта (`project.godot`, `main.tscn`, `scenes/`, `scripts/`, `shaders/`, `assets/`);
- код плагина `addons/godot_mcp/`;
- конфиги (`opencode.json`, `.gitignore`, `.editorconfig`);
- служебные папки (`.godot/`, `.ok/`, `.git/`).

Изменения вне `docs/` выполняются через OpenCode и godot-mcp. При попытке выйти за границы агент обязан остановиться и запросить разрешение.
